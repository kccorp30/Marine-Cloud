# KCC Marine Cloud V9.7 — Phase 3 Mission Control

Phase 3 closes the approved-estimate -> work-order -> technician dispatch -> technician execution loop.

## What changed

### 1. Approved estimate activation
`activate_approved_estimate_work_order()` wraps the existing approved-estimate conversion and then advances only through the canonical `transition_work_order()` state machine until `scheduled`.

No direct `current_status` updates are introduced.

Result:

`Approved estimate -> Activate job -> Scheduled work order -> Dispatch`

### 2. Atomic guided dispatch
New RPC `dispatch_work_order()` validates:
- company staff/KCC access
- active technician membership in the same tenant
- a real schedule
- a work order in `scheduled` or `technician_assigned`

It then atomically:
- creates/reuses the appointment
- assigns/reassigns the technician
- links assignment to appointment
- advances `scheduled -> technician_assigned` through `transition_work_order()`

The server action also sends the assigned technician an operational email.

### 3. Dispatch Mission Card
The work-order page no longer presents separate disconnected "Assign Technician" and "Schedule Visit" cards for staff.

It now has one guided `Service mission` surface with:
- mission progress rail
- assigned technician identity
- technician selector
- schedule
- mission brief
- one Assign & Schedule / Update Dispatch action
- active-mission state once dispatched

### 4. Technician mission controls
The technician can now actually progress the mission from the field:
- Start Route
- Check In
- Start Diagnostic
- Start Work
- Waiting for Parts
- Resume Work
- Send to QC
- Check Out

All status changes call the existing canonical transition function.

### 5. Operations attention
Company owners/admins/managers now receive in-app operational attention when a work order moves to:
- technician en route
- technician arrived
- work started
- QC ready

Customer-facing assignment/en-route/check-in notifications continue to use the existing domain-event notification engine.

### 6. UX
A shared Mission Rail now visualizes the complete lifecycle:
Request -> Triage -> Estimate -> Approval -> Scheduled -> Assigned -> En Route -> On Board -> Diagnostic -> Work -> Parts -> QC -> Invoice -> Payment -> Completed
