# KCC Marine Cloud V9.1 — Auth onboarding hotfix

This release fixes the existing-account regression found immediately after V9 deployment.

## Root cause
V9 used `profiles.password_set_at` as a global route gate. Since that column was new, legacy users had NULL even when they already had a working password. An existing KCC admin could therefore be redirected to `/reset-password?welcome=1` as if invited for the first time.

## Correct behavior
- Existing account + existing session: enter the proper workspace normally.
- Existing account + sign in: email + password, no invitation required.
- New invitation identity: invitation -> create password -> profile -> role home.
- Technician/customer/company users all use email + password after activation.
- First-time setup is explicit account metadata, not guessed from `email_confirmed_at` or a nullable profile column.

## Deployment
1. Deploy this code.
2. Apply `supabase/migrations/20260915233000_auth_setup_state_hotfix.sql` (documentation-only DB hotfix; no destructive changes).
3. Keep the prior V9 credential/invite migration applied when possible, but this release no longer blocks login/onboarding if the profile marker write temporarily fails.
4. Test an existing KCC admin first: open `/login`, sign in, verify direct access without password setup.
5. Test a brand-new company owner invitation end-to-end.

## Critical tests
- Existing KCC admin with legacy account is NOT sent to first-time activation.
- Existing company user signs in with password and reaches company home.
- New owner invite still requires password creation.
- New technician invite still requires password creation and lands on `/today`.
- New customer invite still requires password creation and lands on `/customer`.
- "Already have an account? Sign in" signs the current invite/recovery session out before opening `/login`.
