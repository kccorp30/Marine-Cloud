# KCC Marine Cloud V9.5 — Operations Foundation

This release turns the next stage into an operations-first system instead of adding another visual patch.

## Applied directly to production Supabase

Migration: `20260916013000_operations_attention_and_accounts.sql`

- Technician shift audit regression fixed without widening global audit permissions.
- Company-targeted in-app alerts for new service requests.
- Company-targeted in-app alerts for approved/declined estimates.
- Technician-targeted alert when a job is assigned.
- Company-safe KCC agreement/balance RPC (raw ledger remains KCC-admin-only).
- Customer portal support conversation RPCs.

## Application changes in this ZIP

### Stable navigation shell
- Desktop sidebar is fixed.
- Header stays in the stable application shell.
- Only the workspace content scrolls.
- Horizontal page drift is blocked.

### Company Operations Inbox
- High-priority area on the company home screen.
- New service requests are surfaced immediately.
- Approved estimates are surfaced as ready for action.
- Work orders waiting for a technician are surfaced.
- Luz language guides the operator toward the next action.

### Notifications
- Server reads explicitly scope notifications to the signed-in recipient.
- Company, customer, and technician feeds no longer rely on a broad query.
- Service request, estimate approval, and technician assignment are targeted events.

### Email alerts
- New service requests email company owner/admin/manager.
- Estimate approvals email company owner/admin/manager.
- Technician assignment emails the assigned technician.
- New KCC billing reminder cron emails company owner/admin before/during overdue balances.

### KCC agreement and balance
- Company owner/admin sees current KCC agreement, open balance, open charge count, due date, and overdue state on the main company page.
- Raw KCC ledger is still private to KCC admins.
- Daily Luz billing reminders added at `/api/cron/kcc-billing-reminders`.

### Technician compensation
- Technician dashboard shows pay basis/rate, live workday state, unpaid completed shifts, unpaid gross amount, and last payment.
- Existing technician detail card retains full shift/payment history and pay-term management.

### Customer support
- `/messages` is now a real Marine Support entry point instead of an empty inbox.
- Customer can choose vessel, urgency, subject and message.
- A secure conversation is created and company operations are alerted.
- Customer can reply inside a conversation.

### Estimate email
- Final price removed from the email.
- Premium Marine Cloud visual treatment.
- Strong secure portal CTA.
- Full scope/price/approval remains inside the portal.

### Luz estimate follow-up
- Resend inbound routing is optional.
- Follow-up scheduling now requires only delivery + cron configuration.
- Vercel cron retained every 15 minutes.

### Company logo
- Optional near-black background removal during upload.
- Useful for gold/white logos exported on a black square.

### Error recovery
- Global error screen now offers retry, reload and home recovery actions.
- This improves recovery but the underlying client-navigation race still needs route-by-route tracing.

## Environment variables

Required for email/Luz automation:
- `RESEND_API_KEY`
- `CRON_SECRET`
- `AUTH_FROM_EMAIL` (recommended, verified sender)

Optional:
- `RESEND_INBOUND_DOMAIN`

## Vercel cron jobs

- `/api/cron/luz-followups` — every 15 minutes
- `/api/cron/kcc-billing-reminders` — daily

## Still intentionally separated into Phase 2

These were NOT hacked into the old model in V9.5 because they need a proper data/security design:

1. Customer photos on service requests.
2. Staff photos on estimates and secure customer estimate gallery.
3. Full root-cause trace of the transient `Something went wrong` client-navigation race.
4. Rich sound/preferences layer for high-priority in-app notifications.
5. Payroll due automation for company owners/managers (the technician pay data/card is already present).

The current `media_assets` model requires a work order, so request/estimate photos need a deliberate pre-work-order media extension instead of fake work-order IDs.
