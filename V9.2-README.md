# KCC Marine Cloud V9.2 — invitation delivery resilience hotfix

This hotfix addresses the regression where organization owner and team-member invitations could be created in the database but the recipient did not receive an email.

## What changed

1. **Resend remains the preferred provider.**
2. **Supabase Auth SMTP is now an automatic delivery fallback** for invitation activation emails when Resend is unavailable, misconfigured, rate-limited, or rejects the message.
3. The fallback **does not re-enable passwordless login as the normal login method**. It is used only to deliver the one-time activation link. After activation every role signs in with email + password.
4. Existing first-time password metadata remains intact, so new owners/admins/managers/technicians/customers still create a password during activation.
5. Sender configuration now supports `AUTH_FROM_EMAIL`, plus backwards-compatible `RESEND_FROM_EMAIL` and `EMAIL_FROM_ADDRESS` aliases before using the default sender.
6. If both Resend and Supabase Auth delivery fail, the UI continues returning an explicit delivery error and a manual emergency activation URL instead of falsely reporting success.

## Production configuration to verify

Preferred:

- `RESEND_API_KEY`
- `AUTH_FROM_EMAIL` using a sender/domain verified in the same Resend account
- Supabase Auth SMTP configured and functional as the fallback path
- `NEXT_PUBLIC_SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- correct public site URL (`NEXT_PUBLIC_SITE_URL` / existing site-url configuration)

## Recommended smoke tests

1. Create a company with a never-used owner email.
2. Confirm invitation email arrives.
3. Accept invite, create password, reach `/company`.
4. Sign out and sign in with email + password.
5. Invite a technician.
6. Invite a manager/company admin.
7. Resend a pending invitation.
8. Temporarily use an invalid Resend key in a staging environment and verify the Supabase Auth SMTP fallback still delivers the activation email.
9. Verify no duplicate `auth.users`, organization memberships, or pending invitations are created.

## Important

The V9/V9.1 authentication model is preserved. This release changes delivery resilience, not the permanent login model.
