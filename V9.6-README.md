# KCC Marine Cloud V9.6 — Phase 2: Media + Communication

## What this release adds

### 1. Photos on customer service requests
- Customers can attach up to 5 photos when requesting service.
- Browser optimizes modern phone photos before upload when possible.
- Supported: JPG, PNG, WebP, HEIC, HEIF.
- Storage is private.
- Staff sees the customer photos directly inside Service Requests.
- Operational email mentions how many photos were attached.

### 2. Photos on estimates
- Company staff can add real vessel/service photos directly to an estimate.
- Categories: Reference, Damage/Issue, Diagnosis, Before, Progress, After.
- Optional caption.
- Customer sees the gallery inside the secure estimate portal.
- If the estimate came from a service request, the request photos are automatically shown in the estimate too — no re-upload required.
- Estimate email still keeps sensitive scope and pricing inside the secure portal.

### 3. Visual support conversations
- Customer support form now accepts photos.
- Support thread has a real visual gallery.
- Customer and staff can continue adding images without leaving the conversation.
- All uploads remain inside a private Supabase bucket and are displayed with short-lived signed URLs.

### 4. Support → Service Request
- Staff can convert a customer support conversation into a service request with one action.
- Customer + vessel + conversation context are reused.
- Existing support photos are copied into the resulting service request so visual context is preserved.
- Company attention notifications continue using the operations layer introduced in V9.5.

## New database/storage architecture

### `entity_media_attachments`
Generalized media metadata for entities that exist before a work order:
- `service_request`
- `estimate`
- `conversation`

This intentionally does not overload the existing `media_assets` work-order evidence table, whose invariants require a work order.

### Storage bucket
`portal-media`
- private
- max source object: 12 MB
- image MIME allow-list only
- user browsers never receive a service-role key
- server creates short-lived signed read URLs after RLS authorization

## Security model
- Upload write path is server-side only after explicit role/entity authorization.
- Authenticated users receive no direct INSERT/UPDATE/DELETE on `entity_media_attachments`.
- Customer SELECT is allowed only for their own service request, estimate, or conversation and only when visibility is `customer_visible`.
- Staff continues to be limited by tenant membership.
- KCC admin keeps platform visibility.
